# STCT 受控内部试用脚本（V87）

状态：PREPARED；真人观察 NOT_RUN。Windows 实机与真实 OSRM 为 DEFERRED_BY_USER；正式 v1.8 Soak 为 DEFERRED_BY_USER。此版本不是生产上线。

## 启动与身份核对

项目根目录执行 `python3 scripts/local_trial.py start --web-port 8865 --opt-port 8887`，打开 `http://127.0.0.1:8865/index.html?optPort=8887#/`。必须使用已有 OR-Tools 的解释器。端口占用会拒绝启动；不停止占用进程。页面与原生后台的版本必须匹配。试用结束仅执行本项目入口的 `python3 scripts/local_trial.py stop`，核对记录归属；不使用模糊进程结束命令。

## 参与者任务

业务同事在观察者不代操作的情况下完成：

1. 从首页导入获准测试副本；核对 Sheet、角色、单位、期间和统计边界。不要编辑配置 JSON。
2. 先选择仅配送范围，保留现状归属；确认地理筛选条件，改仓数后分析。再分别查看固定仓网上游和全链范围。
3. 指出参照类型：观察现状、已知供应商观察入库或同条件规划参照。解释为何不能强行对平历史入出库。
4. 从比较表选择另一候选，确认地图候选、距离卡片、仓负荷及明细一致。指出正式决策摘要不因查看候选而变成新推荐。
5. 在同屏切换参照／候选／叠加、期间、运输段、只看变化和节点。展开关系物量表，定位一个供应商或仓库；说明新增、取消和物量变化的含义。
6. 说明改善发生在哪一段、另一段是否变差、有哪些费用或能力缺口。地图连线是分配关系；地理改善不是实际道路或经营节省。
7. 保存研究，从公共情景库重开，导出报告与可回读研究包，刷新后检查身份与结果。改变条件后确认旧结果失效。
8. 返回运输运营，分别找到排车、执行、告警、恢复和报告的入口；仅用获准合成运营数据，不将 UC 月度物量当派车订单。

## 记录方式

使用同目录 `HUMAN_TRIAL_RECORD.csv`。记录实际参与者匿名编号、任务、成功与否、耗时、求助次数、误解和截图引用；每个失败记录最小复现步骤。观察者提示必须记录，不把提示后完成当作独立完成。没有参与者时保留空表，不生成评价或成功率。

## 退出与反馈

参与者不能解释参照、距离／费用／能力边界，或发生研究丢失、候选混淆、结果过期仍导出，均属于阻止放行的问题。收集真实反馈后再做针对性 UI 调整，不用自动化截图替代观察。按最终源码版本和测试矩阵记录试用结果。

## 地图决策体验补充任务（本轮）

以下为准备好的观察任务，尚无真人结果。使用同目录空白记录表填写真实记录。

1. 在供应链设计结果页或仓网地图中找到“并排对照”。解释左侧参照属于观察现状、已知入库还是同条件规划参照，指出右侧正在查看的候选名称。
2. 在任意一边拖动、缩放，检查另一边视野同步。点击仓库颜色图例，找出一个改变的服务或供货关系；说明新增/取消关系没有改变原业务物量。再次点击同一仓名或“返回全网”恢复。
3. 在右侧清单搜索一个对象并查看关系详情，解释原/新物量、距离、费用未知项以及逐期记录。通过“关系变化”和“期间”控件核对范围；全期距离卡片与期间地图不要混用。
4. 切换候选，再次指出参照和方案。正式推荐不会因为查看另一个候选而改变；地理缩距不能作为实施节省。
5. 在390px或手机上下对照，并打印检查两侧标题、颜色及关系。No-WebGL使用同一结果投影的示意图，不宣称加载了道路底图。
6. 保存回读、刷新及导出；比较操作不改研究输入、模型数量、求解结果和研究包哈希。

记录是否独立完成、耗时、求助、参照误解和选错方案。没有参与者时保持 NOT_RUN；Windows实机和真实OSRM仍待用户移回Windows后验收。
