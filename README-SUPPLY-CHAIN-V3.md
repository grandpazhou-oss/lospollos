# 供应链网络设计：业务操作流程

在现有 STCT 本地页面进入「DESIGN → 供应链网络设计」。本地求解服务仍需按项目现有方式启动；页面会显示连接状态并提供重试。

1. **上传数据。** 选择 Excel 或 CSV。系统按工作表结构、表头和期间列匹配已保存的映射。核对预览中的角色、字段、单位、期间与数量，然后点击「确认映射并继续」。未匹配时用列下拉框和期间行完成映射，无需编写 JSON。UC 映射保存在独立的 `profiles/` 配置中。
2. **确认分析条件。** 选择距离、费用或覆盖目标；按仓库名称设定必留、可调整、可关闭，以及仓数范围。只有地理距离资料时，须明确确认坐标假设；结果只是地理筛选，不是道路里程或已验证时效。可选地补充有向道路距离表、费率、各仓逐期容量和方案供货来源。未知值保持空白。映射完成和有效条件变化后会在本机保存草稿。
3. **开始分析并查看结果。** 点击一次「开始分析」，系统依次检查本地求解服务、保存配置、按原归属核算现状、求解与校验候选、生成比较结果。报告和明细下载使用同一结果快照。修改条件后需要重新分析，旧结果不能作为当前正式报告导出。已保存研究可以按名称、时间和状态从卡片重开。

UC 验收文件上传后使用已注册映射。若没有道路矩阵、费率、库存或容量证据，页面只给出标明缺口的配送地理筛选，不给财务或实施推荐。原始 Excel 不会被覆盖。

浏览器验收脚本 `tests/test_supply_chain_browser_v19.js` 使用不同表头的合成文件，`tests/test_supply_chain_uc_browser_v19.js` 使用 UC 文件的临时副本。两者均通过页面上传和业务控件操作，不向页面写入配置 JSON。
