## Direction

The interface uses a white and cool-gray operational field, deep navy text, thin neutral rules, and small red/blue status signals. It avoids dark-tech styling, gradients, glow, marketing composition, decorative cards, and motion without operational meaning.

## Required Scenarios

1. Desktop Multi-Vehicle Operations: shared fleet clock, patterned tracks, vehicle table, and driver workflow.
2. Desktop Verified Telemetry Inspector: Reported and Derived values remain visibly distinct; confidence is text, not color alone.
3. Desktop Shift Review: route small multiples, Flight Recorder, unresolved items, and long description.
4. Desktop Offline Conflict Center: dependency chain plus explicit keep, retry, and discard actions.
5. Mobile Offline Multi-step Driver: current stop, readable offline state, and step buttons above the safe area.
6. Mobile Conflict Resolution: one conflict per scan unit with touch-sized alternatives.
7. Reduced Motion Fleet Replay: static step controls; no autoplay is required to understand state.
8. No-WebGL Shift Review: complete table equivalent and long description without a canvas dependency.

## Interaction Contract

- Every primary command changes domain state, focus selection, or creates a download.
- Stream refresh never moves keyboard focus.
- `POSITION_RECORDED` is not sent to the ARIA live region.
- Hover interactions have click, tap, or focus equivalents.
- Timeline and fleet selection have keyboard step controls.
- Color is duplicated by text, icon, and track pattern.
- Mobile layouts use `env(safe-area-inset-bottom)` and do not require dragging.

## Boundaries

- Local synthetic execution, not a live fleet.
- Synthetic telemetry, not live GPS.
- SVG track layer is a local operational visualization, not a road-navigation claim.
- Physical iPhone Safari measurement: `BLOCKED_MEASUREMENT` until run on a real device.
